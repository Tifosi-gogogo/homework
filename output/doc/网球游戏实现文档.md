# C++ 网球对战游戏实现文档

## 1. 项目定位

项目名称建议：`Campus Tennis`、`网球对决`、`Tennis Duel`，任选一个正式名称即可。

项目类型：C++ 图形化 2D 网球对战游戏。

推荐图形库：`Qt 6 Widgets + CMake + C++17`。

选择 Qt 的原因：

- Qt 是成熟的 C++ 图形化框架，符合课程“图形化平台不限，可以是 MFC、QT 等”的要求。
- `Qt Widgets` 适合做菜单、商店、角色选择、结算界面等传统桌面 UI。
- `QWidget + QPainter` 可以完成球场、人物、网球和抛物线效果的 2D 绘制。
- `QTimer` 可以驱动固定帧率游戏更新，避免手写阻塞式 `while` 主循环。
- `QSettings` 或普通文本文件可以实现金币、签到、装备等本地存档。
- Qt 工程可以使用 CMake 管理，后续提交到 Gitee/GitHub 时结构更清晰。

可替代方案仅作为了解：

- `SFML`：游戏开发体验好，但 UI 商店和菜单需要自己做更多控件。
- `MFC`：适合传统 Windows 桌面程序，但写游戏界面不如 Qt 灵活。
- `EasyX`：上手快，但本项目已明确要求使用 Qt，因此不采用。

本实现文档默认使用 Qt 6 Widgets。核心游戏逻辑尽量写成普通 C++ 类，Qt 主要负责窗口、输入、绘制、页面切换和资源管理。

## 3. 游戏需求整理

### 3.1 游戏模式

游戏包含两种模式：

- 单人模式：玩家对战人机。
- 双人模式：本地双人对战。

单人模式控制：

- 玩家移动：方向键 `Up / Down / Left / Right`。
- 接球/击球：`Space`。
- 对手由 AI 控制。

双人模式控制：

- P1 移动：`W / A / S / D`。
- P1 击球：`Space`。
- P2 移动：方向键。
- P2 击球：`J`。

双人模式不再共用一个击球键，避免两名玩家同时抢按时归属不清：

- P1 发球和击球只响应 `Space`。
- P2 发球和击球只响应 `J`。
- 如果玩家不在击球范围内，按自己的击球键只显示距离不足反馈，不会替另一名玩家击球。

### 3.2 比赛结构

需求中写到“只设置 3 盘，3 局 2 胜，局内规则和正常网球规则相同”。为了控制大作业范围，推荐解释为：

- 一场比赛最多 3 局。
- 先赢 2 局的一方赢得整场比赛。
- 每一局内部使用标准网球计分：`0 / 15 / 30 / 40 / Deuce / Advantage / Game`。

不建议完整实现职业网球里的“盘、局、抢七”系统，因为工程量会明显增加，而且会影响主要游戏体验。报告里可以说明本项目采用“简化赛制 + 标准局内计分”。

### 3.3 局内计分规则

每局开始时比分为 `0 : 0`。

计分变化：

| 当前分 | 得分后 |
|---|---|
| 0 | 15 |
| 15 | 30 |
| 30 | 40 |
| 40 且对手小于 40 | 赢得本局 |
| 双方 40 | Deuce |
| Deuce 后一方得分 | Advantage |
| Advantage 方再得分 | 赢得本局 |
| Advantage 方失分 | 回到 Deuce |

整场比赛：

- P1 局数达到 2：P1 获胜。
- P2 局数达到 2：P2 获胜。
- 最多打 3 局。

### 3.4 每分开始和结束

每一分的流程：

1. 发球方站在底线附近。
2. 玩家按击球键发球，或者系统倒计时后自动发球。
3. 球飞过球网，落入对方半场。
4. 对方移动到球附近，在合理时间窗口内按击球键。
5. 成功击球后，球飞向对方半场。
6. 出界、下网、未接到、二次落地时，该分结束。

建议实现的失分条件：

- 球第一次落地时不在对方有效半场内：击球方失分。
- 球碰到球网且没有过网：击球方失分。
- 球在一方半场第二次落地仍未被击回：接球方失分。
- 玩家处于击球范围外，或击球概率判定失败：接球方失分。

可选实现发球规则：

- 每分有两次发球机会。
- 第一次发球未过网或出界，显示 `Fault`。
- 第二次发球失败，显示 `Double Fault`，接发球方得分。

如果时间不够，可以先实现“自动合法发球”，保证主要回合体验。

## 5. 坐标系统与物理设计

### 5.1 球场坐标

推荐使用逻辑坐标，不要直接把所有东西写死在屏幕像素上。

逻辑球场：

- `x`：左右方向。
- `y`：前后方向。
- `z`：高度。
- 球网位于 `y = 0`。
- P1 半场在 `y > 0`。
- P2 半场在 `y < 0`。

参考真实尺寸：

- 单打球场宽度：8.23 米。
- 球场长度：23.77 米。
- 半场长度：11.885 米。
- 球网高度：约 0.914 米。

为了游戏体验，可以使用缩放后的逻辑尺寸：

```cpp
const double COURT_HALF_WIDTH = 4.115;
const double COURT_HALF_LENGTH = 11.885;
const double NET_Y = 0.0;
const double NET_HEIGHT = 0.914;
const double GRAVITY = 9.8;
```

绘制时再转换成屏幕坐标：

```cpp
screenX = courtCenterX + x * scale;
screenY = courtCenterY + y * scale - z * heightScale;
```

其中：

- `x, y` 决定球在球场平面上的位置。
- `z` 决定球的高度。
- `- z * heightScale` 让球在屏幕上向上偏移，形成抛物线视觉。

### 5.2 网球运动方程

网球状态：

```cpp
struct Ball {
    Vec3 pos;      // x, y, z
    Vec3 vel;      // vx, vy, vz
    bool active;
    int lastHitPlayer;      // 1 或 2
    int expectedReceiver;   // 下一位应该接球的玩家
    int bounceCountOnSide;  // 当前半场内已落地次数
};
```

每帧更新：

```cpp
pos.x += vel.x * dt;
pos.y += vel.y * dt;
pos.z += vel.z * dt;
vel.z -= GRAVITY * dt;
```

落地反弹：

```cpp
if (pos.z <= 0) {
    pos.z = 0;
    vel.z = -vel.z * bounceFactor;  // bounceFactor 推荐 0.45 到 0.65
    vel.x *= 0.92;
    vel.y *= 0.92;
    bounceCountOnSide++;
}
```

注意：网球不是一直弹下去。游戏中需要在第二次落地时直接判定接球方失分。

### 5.3 生成一次击球轨迹

击球时不要随便给速度，推荐根据“当前位置”和“目标落点”反推初速度。

给定：

- 当前球位置 `start`。
- 目标落点 `target`。
- 预计飞行时间 `T`。
- 重力加速度 `g`。

速度计算：

```cpp
vel.x = (target.x - start.x) / T;
vel.y = (target.y - start.y) / T;
vel.z = (target.z - start.z + 0.5 * g * T * T) / T;
```

其中 `target.z = 0`，表示目标是落在地面。

这样计算出来的轨迹天然是抛物线，视觉上符合物理逻辑。

飞行时间建议：

```cpp
double distance = sqrt(dx * dx + dy * dy);
double T = clamp(distance / shotSpeed, 0.55, 1.35);
```

不同击球类型可以调整 `shotSpeed` 和 `T`：

| 击球类型 | 特点 | T |
|---|---|---|
| 平击 | 速度快、弧线低 | 0.55-0.85 |
| 上旋 | 中速、弧线稳定 | 0.75-1.05 |
| 高吊 | 慢、弧线高 | 1.10-1.45 |
| 小球 | 近网落点、速度慢 | 0.70-1.10 |

### 5.4 网球视觉表现

为了让抛物线明显，建议绘制三部分：

1. 网球本体：根据 `x, y, z` 绘制。
2. 地面阴影：根据 `x, y` 绘制，不受 `z` 影响。
3. 球大小变化：`z` 越高，球略微变大或颜色更亮。

绘制伪代码：

```cpp
Point shadow = courtToScreen(ball.pos.x, ball.pos.y, 0);
Point ballPoint = courtToScreen(ball.pos.x, ball.pos.y, ball.pos.z);

drawShadow(shadow.x, shadow.y);
drawBall(ballPoint.x, ballPoint.y, baseRadius + ball.pos.z * 0.8);
```

视觉效果：

- 阴影贴在地面，表示球的水平位置。
- 球本体随着 `z` 上升而在屏幕上向上偏移。
- 玩家能看出球是在空中还是快落地。

## 6. 击球判定设计

### 6.1 击球条件

玩家成功击球需要同时满足：

- 球在该玩家半场或可接球区域。
- 玩家距离球的水平投影足够近。
- 球的高度在可击球范围内。
- 玩家在合理时间窗口内按下击球键。
- 概率判定成功。

推荐参数：

```cpp
const double BASE_HIT_RADIUS = 0.85;   // 米
const double MIN_HIT_HEIGHT = 0.15;
const double MAX_HIT_HEIGHT = 2.20;
```

距离判定：

```cpp
double dist = distance2D(player.pos, ball.pos);
bool inRange = dist <= BASE_HIT_RADIUS + racket.rangeBonus;
```

高度判定：

```cpp
bool heightOK = ball.pos.z >= MIN_HIT_HEIGHT && ball.pos.z <= MAX_HIT_HEIGHT;
```

### 6.2 最佳击球时刻

需求中的“0.1s、0.2s、0.5s、1s、1.5s 内”需要有一个参照点。推荐定义为：

最佳击球时刻 = 球进入玩家可击球范围，并且球高度适合击球的那一刻附近。

实现方式：

- 每帧检查球是否进入某玩家的击球范围。
- 第一次进入范围时记录 `hitOpportunityStartTime`。
- 玩家按下击球键时，计算 `dt = 当前时间 - hitOpportunityStartTime`。
- 根据 `dt` 查表得到基础命中概率。

这样更容易实现，也符合玩家感受：球到身边后越快按键，成功率越高。

也可以使用更精确的做法：

- 预测球离玩家最近的时间作为 `bestHitTime`。
- 计算 `dt = abs(pressTime - bestHitTime)`。

大作业中推荐第一种，代码更稳定。

### 6.3 基础命中概率

按需求实现如下：

| 按键时间窗口 | 基础命中概率 |
|---|---:|
| 0.1 秒内 | 100% |
| 0.2 秒内 | 90% |
| 0.5 秒内 | 80% |
| 1.0 秒内 | 50% |
| 1.5 秒内 | 10% |
| 超过 1.5 秒 | 0% |

函数设计：

```cpp
double getBaseHitProbability(double dt) {
    if (dt <= 0.1) return 1.00;
    if (dt <= 0.2) return 0.90;
    if (dt <= 0.5) return 0.80;
    if (dt <= 1.0) return 0.50;
    if (dt <= 1.5) return 0.10;
    return 0.0;
}
```

### 6.4 球拍加成

需求中要求“网球拍越贵，击中网球的概率越高”。推荐让球拍同时影响：

- 命中概率。
- 击球范围。
- 控球稳定性。

球拍数据：

| 球拍 | 价格 | 命中概率加成 | 击球范围加成 | 控球误差 |
|---|---:|---:|---:|---:|
| 训练球拍 | 1000 | +3% | +0.05m | +/-1.00m |
| 轻量球拍 | 1500 | +5% | +0.08m | +/-0.85m |
| 碳素球拍 | 2000 | +7% | +0.11m | +/-0.70m |
| 专业球拍 | 2500 | +10% | +0.15m | +/-0.55m |
| 传说球拍 | 5000 | +15% | +0.22m | +/-0.35m |

概率计算：

```cpp
double finalProbability = baseProbability + racket.hitBonus;
finalProbability = min(finalProbability, 1.0);
```

示例：

- 0.5 秒内基础 80%。
- 使用专业球拍加 10%。
- 最终概率为 90%。

注意：

- 0.1 秒内本来就是 100%，球拍不需要再提高。
- 概率上限必须是 100%。
- 建议在 UI 里显示球拍属性，让商店有价值感。

### 6.5 概率随机实现

使用 C++ 标准随机数：

```cpp
#include <random>

class Random {
public:
    Random() : engine(std::random_device{}()) {}

    double real(double minValue, double maxValue) {
        std::uniform_real_distribution<double> dist(minValue, maxValue);
        return dist(engine);
    }

private:
    std::mt19937 engine;
};
```

判定：

```cpp
bool success = random.real(0.0, 1.0) <= finalProbability;
```

### 6.6 击球成功后的目标点

成功击球后，需要决定球飞到哪里。

玩家击球的简化目标：

- 默认打向对方半场中心。
- 根据玩家移动方向加入偏移。
- 根据球拍控球误差加入随机偏移。

示例：

```cpp
Vec3 chooseHumanTarget(const Player& player, const Racket& racket) {
    Vec3 target;
    target.y = player.side == 1 ? -7.5 : 7.5;
    target.x = 0;

    if (player.input.left)  target.x -= 1.8;
    if (player.input.right) target.x += 1.8;
    if (player.input.up)    target.y += player.side == 1 ? -1.5 : 1.5;
    if (player.input.down)  target.y += player.side == 1 ? 1.0 : -1.0;

    target.x += random.real(-racket.controlError, racket.controlError);
    target.y += random.real(-racket.controlError, racket.controlError);
    target.z = 0;
    return clampToOpponentCourt(target);
}
```

这样玩家可以通过方向键影响回球方向，球拍越好，误差越小。

## 7. 人机 AI 设计

### 7.1 难度等级

人机分为三档：简单、普通、困难。

| 难度 | 移动速度 | 反应延迟 | 接球概率 | 回球不规律程度 | 策略 |
|---|---:|---:|---:|---:|---|
| 简单 | 低 | 0.45s | 55% | 低 | 常打中路，容易预判 |
| 普通 | 中 | 0.28s | 75% | 中 | 左右调动，有少量随机 |
| 困难 | 高 | 0.12s | 92% | 高 | 大角度、短球、高吊混合 |

说明：

- “难度更高，接球概率更高”对应接球概率字段。
- “回击球更不规律”对应目标点随机、击球类型变化和落点变化。
- 困难 AI 不应每球都打死角，否则游戏体验会过难。建议让它高概率有效，但仍有失误。

### 7.2 AI 移动逻辑

AI 每帧做三件事：

1. 预测球落到自己半场的大致位置。
2. 向预测位置移动。
3. 球进入击球范围后，根据难度概率决定是否击球。

伪代码：

```cpp
void AIController::update(Player& ai, const Ball& ball, double dt) {
    if (!isBallComingToAI(ball)) {
        moveToHomePosition(ai, dt);
        return;
    }

    Vec2 target = predictLandingPoint(ball);
    target = addDifficultyError(target);
    moveToward(ai, target, dt);

    if (canTryHit(ai, ball) && reactionTimer.finished()) {
        tryAIHit(ai, ball);
    }
}
```

### 7.3 AI 接球概率

AI 的最终接球成功率可以由两部分构成：

```cpp
finalAIHitProbability = difficulty.baseReceiveProbability;
```

如果想更细致，可以加入距离影响：

```cpp
double distPenalty = clamp(dist / maxHitDistance, 0.0, 1.0) * 0.20;
finalAIHitProbability = baseProbability - distPenalty;
```

困难 AI 也会因为离球太远而失败，避免显得不公平。

### 7.4 AI 回球不规律

AI 回球目标点：

```cpp
Vec3 AIController::chooseTarget(Difficulty diff) {
    if (diff == Easy) {
        return targetNearCenter();
    }
    if (diff == Normal) {
        return randomChoice(center, left, right, deep);
    }
    if (diff == Hard) {
        return randomChoice(leftCorner, rightCorner, shortBall, lob, deepFast);
    }
}
```

推荐参数：

| 难度 | x 随机范围 | y 随机范围 | 击球类型 |
|---|---:|---:|---|
| 简单 | +/-1.0m | +/-1.0m | 平稳回球 |
| 普通 | +/-2.3m | +/-2.0m | 平击/上旋 |
| 困难 | +/-3.5m | +/-3.2m | 平击/上旋/高吊/小球 |

“不规律”不是完全随机到出界，而是在有效球场范围内做更多变化。

### 9.1 存档内容

void ScoreSystem::addPoint(int winner) {
    PointValue& winPoint = winner == 1 ? p1Point : p2Point;
    PointValue& losePoint = winner == 1 ? p2Point : p1Point;

    if (winPoint == PointValue::Advantage) {
        winGame(winner);
        return;
    }

    if (losePoint == PointValue::Advantage) {
        losePoint = PointValue::Forty;
        winPoint = PointValue::Forty;
        return;
    }

    if (winPoint == PointValue::Forty && losePoint == PointValue::Forty) {
        winPoint = PointValue::Advantage;
        return;
    }

    if (winPoint == PointValue::Forty) {
        winGame(winner);
        return;
    }

    advancePoint(winPoint);
}

Qt 中建议通过 `keyPressEvent` 和 `keyReleaseEvent` 维护输入状态：

```cpp
void GameWidget::keyPressEvent(QKeyEvent* event) {
    if (event->isAutoRepeat()) {
        return;
    }
    input.setKeyDown(event->key(), true);
}

void GameWidget::keyReleaseEvent(QKeyEvent* event) {
    if (event->isAutoRepeat()) {
        return;
    }
    input.setKeyDown(event->key(), false);
}
```

`InputManager` 内部仍然需要区分“当前按住”和“本帧刚按下”。例如 `Space` 在 `keyPressEvent` 中标记为 P1 本帧击球，`J` 标记为 P2 本帧击球，`MatchController::update` 处理完后调用 `input.finishFrame()` 清除一次性状态。

### 11.2 双人模式击球归属

双人模式击球不做自动归属，而是按键和玩家一一对应：

1. `Space` 被按下时，只检查 P1 是否处于可击球状态。
2. `J` 被按下时，只检查 P2 是否处于可击球状态。
3. 如果对应玩家不在击球范围内，只给出距离不足反馈。
4. 不再根据距离自动替另一名玩家击球。

伪代码：

```cpp
if (input.p1HitPressed) {
    tryHit(p1);
}
if (input.p2HitPressed) {
    tryHit(p2);
}
```

## 14. 核心算法伪代码

### 14.1 Qt 游戏刷新流程

```cpp
GameWidget::GameWidget(QWidget* parent) : QWidget(parent) {
    setFocusPolicy(Qt::StrongFocus);
    elapsedTimer.start();

    connect(&frameTimer, &QTimer::timeout, this, &GameWidget::tick);
    frameTimer.start(16);
}

void GameWidget::tick() {
    double dt = elapsedTimer.restart() / 1000.0;

    match.update(input.currentState(), dt);
    input.finishFrame();

    update();
}

void GameWidget::paintEvent(QPaintEvent*) {
    QPainter painter(this);
    painter.setRenderHint(QPainter::Antialiasing, true);

    match.draw(painter);
}
```

Qt 的关键点：

- `QTimer` 负责按固定间隔调用 `tick`。
- `tick` 中只做逻辑更新，不直接画图。
- `update()` 会请求 Qt 触发 `paintEvent`。
- 所有绘制集中在 `paintEvent` 中使用 `QPainter` 完成。
- 不在 Qt 主线程里写阻塞式 `while (running)` 游戏循环。

### 14.2 击球流程

```cpp
void MatchController::tryHit(Player& player) {
    if (!canHit(player, ball)) {
        return;
    }

    double dt = currentTime - player.hitOpportunityStartTime;
    double base = getBaseHitProbability(dt);
    double finalProb = min(1.0, base + player.racket.hitBonus);

    if (random.real(0.0, 1.0) > finalProb) {
        endPoint(opponentOf(player.id));
        showFeedback("Miss");
        return;
    }

    Vec3 target = chooseTarget(player);
    double flightTime = chooseFlightTime(player, target);
    ball.launchTo(target, flightTime);
    ball.lastHitPlayer = player.id;
    ball.expectedReceiver = opponentOf(player.id);
    ball.bounceCountOnSide = 0;

    showHitFeedback(dt);
}
```

### 14.3 回合失分判断

```cpp
void MatchController::checkBallRules() {
    if (ballHitsNet()) {
        endPoint(opponentOf(ball.lastHitPlayer));
        return;
    }

    if (ballFirstBounceJustHappened()) {
        if (!isInsideExpectedCourt(ball.pos, ball.expectedReceiver)) {
            endPoint(opponentOf(ball.lastHitPlayer));
            return;
        }
    }

    if (ball.bounceCountOnSide >= 2) {
        endPoint(ball.lastHitPlayer);
        return;
    }
}
```

注意：

- `ball.lastHitPlayer` 是上一拍击球的人。
- 如果对手没有在二次落地前接到，上一拍击球的人得分。

### 14.4 比分更新

```cpp
void MatchController::endPoint(int winner) {
    scoreSystem.addPoint(winner);

    if (scoreSystem.isMatchOver()) {
        phase = MatchPhase::MatchOver;
        handleMatchReward();
    } else {
        resetForNextPoint();
    }
}
```

### 14.5 结算金币

```cpp
void MatchController::handleMatchReward() {
    int winner = scoreSystem.getMatchWinner();

    if (winner == localPlayerId || mode == TwoPlayer) {
        saveData.coins += 20;
        saveData.winCount++;
        saveManager.save(saveData);
    }
}
```

双人模式如果只有一个本地存档，可以给胜者所属玩家加到同一个金币账户。报告中说明“本游戏采用本地单账户金币系统”即可。

## 20. 常见问题与处理

### 20.1 球速太快，玩家接不到

处理：

- 降低水平速度。
- 增大飞行时间 `T`。
- 增大基础击球范围。
- 让球第一次落地后仍能接。

### 20.2 球的抛物线不明显

处理：

- 增大 `heightScale`。
- 增大 `vel.z`。
- 给球增加阴影。
- 球越高画得略大一些。

### 20.3 AI 太强

处理：

- 增大反应延迟。
- 降低移动速度。
- 降低接球概率。
- 增加目标点误差。

### 20.4 AI 太弱

处理：

- 提高预测落点准确度。
- 提高移动速度。
- 提高接球概率。
- 减少无意义随机。

### 20.5 击球概率体验不明显

处理：

- 击球后显示 `Perfect / Good / Late / Miss`。
- 在调试模式显示 `dt` 和最终概率。
- 让高级球拍明显减少失误。

### 20.6 商店金币太难攒

需求指定赢一场 20 金币、签到 10 金币。如果觉得节奏太慢，不建议随意改奖励。可以通过以下方式改善：

- 初始赠送基础套装和基础球拍。
- 最便宜服装设置为 200 金币。
- 球拍价格按需求设置为 1000 到 5000 金币。
- 报告中说明金币系统用于长期游玩，完整购买不是一次作业演示必须达成。
